# Implementation Plan: GitHub Pages Module Documentation

**Branch**: `005-github-pages-docs` | **Date**: 2026-05-13 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `specs/005-github-pages-docs/spec.md`

## Summary

Publish a static documentation site to GitHub Pages that covers all 13 `internal/modules` of ai-check-guardrails, the module interface contract, configuration reference, and severity levels. Local preview is available via `make preview-docs` (uses `uvx --with mkdocs-material`). CI deployment runs on every push to `main` via a new `.github/workflows/docs.yml` workflow using the official `actions/deploy-pages` action.

## Technical Context

**Language/Version**: Go 1.26.2 (existing codebase); Python environment provided via `uvx` (no global install)  
**Primary Dependencies**: mkdocs-material (docs only, not added to go.mod)  
**Storage**: N/A — static site; no runtime data  
**Testing**: `make build-docs` must exit 0 (mkdocs strict mode catches broken links)  
**Target Platform**: GitHub Pages (static hosting); local dev on Linux/macOS  
**Project Type**: Documentation feature added to existing CLI tool  
**Performance Goals**: Site builds in under 60 seconds; `make preview-docs` starts in under 30 seconds  
**Constraints**: No new Go dependencies; documentation tooling is isolated in `uvx` environment  
**Scale/Scope**: 13 module pages + 3 reference pages + 1 index = 18 pages total

## Implementation Phases

### Phase A: Infrastructure (Makefile + mkdocs.yml + workflow)

1. Create `mkdocs.yml` at repo root (see contracts/mkdocs-config.md for schema)
2. Create `Makefile` with `preview-docs` and `build-docs` targets
3. Create `.github/workflows/docs.yml` with build + deploy jobs
4. Add `site/` to `.gitignore`

**Acceptance**: `make build-docs` exits 0; `make preview-docs` starts server at port 8000.

### Phase B: Reference Pages (module interface + config + severity)

1. `docs/reference/module-interface.md` — Module interface contract (Name/Enabled/Run) and Finding struct fields
2. `docs/reference/config.md` — Full config key reference table (all keys from `internal/config/config.go`)
3. `docs/reference/severity.md` — Severity enum table with meaning and score impact

**Acceptance**: All three pages render in local preview with correct content from source.

### Phase C: Module Pages (×13)

For each module, create `docs/modules/<name>.md` with:
- Purpose section (one paragraph)
- Findings table (type, severity, description, remediation)
- Configuration section (enable key + any extra keys)

Modules: banner, bypass, envkeys, evals, gamification, hooks, humanloop, mcp, network, permissions, sandbox, settings, tokens.

**Acceptance**: All 13 module pages accessible from `docs/modules/index.md`; findings tables are complete (no module finding types omitted).

### Phase D: Index Pages

1. `docs/index.md` — Landing page: project overview, quick link to modules, link to GitHub releases
2. `docs/modules/index.md` — Module list table (name, purpose, default state)

**Acceptance**: Visitor arriving at site root can reach any module page within one click.
